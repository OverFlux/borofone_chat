# Развёртывание

Локальный Windows-хост запускается через `START_BOROTALK.bat`. Скрипт поднимает
PostgreSQL и Redis, применяет Alembic, готовит HTTPS и создаёт `.borotalk`
инвайт.

Перед запуском приложения лаунчер создаёт два более специфичных маршрута
`26.0.0.0/9` и `26.128.0.0/9` через адаптер Radmin. Вместе они покрывают сеть
Radmin `26.0.0.0/8` и не дают другому полнотуннельному VPN перехватить её
равным или менее специфичным маршрутом. Для ручного восстановления используется
`FIX_RADMIN_ROUTE.bat`.

Если сторонний VPN применяет KillSwitch через собственный сетевой фильтр,
маршрута недостаточно: в VPN-клиенте нужно исключить `26.0.0.0/8` из туннеля
и отключить KillSwitch.

Docker-конфигурации staging и production находятся в `deploy/docker`.
GitHub Actions запускает `deploy/scripts/deploy-stack.sh`.

Runtime-данные хранятся вне Git:

- PostgreSQL и Redis — Docker volumes;
- аватары — `${HOST_DATA_ROOT}/uploads`;
- сертификаты и локальные инвайты — на хосте.

Перед обновлением deployment-конфигурации нельзя переименовывать существующие
PostgreSQL/Redis volumes без отдельной миграции: старые технические имена
сохранены намеренно ради совместимости с уже развёрнутыми данными.
