# Borotalk на своём VPS: инструкция с нуля

Эта инструкция рассчитана на человека, который раньше не разворачивал
Borotalk. В результате приложение будет открываться по обычному HTTPS-домену,
например `https://talk.example.com`, а пользователям не понадобятся Radmin VPN
или отдельный сервер на домашнем компьютере.

## 1. Что подготовить заранее

Понадобятся:

- VPS с Ubuntu 22.04/24.04 или Debian 12, архитектура x64;
- минимум 2 ГБ RAM, 2 vCPU и 20 ГБ свободного диска;
- публичный IPv4 и доступ к VPS по SSH с правами `root` или `sudo`;
- собственный домен и доступ к его DNS-записям;
- внешний транзакционный SMTP с портом `587` и STARTTLS;
- Telegram-бот, созданный через `@BotFather`.

Для голосовых разговоров и особенно TURN-трансляций важен исходящий трафик
VPS. Если провайдер ограничивает месячный трафик, учитывайте это при выборе
тарифа.

## 2. Настроить домен

Допустим, Borotalk должен открываться как `talk.example.com`, а IPv4 VPS —
`203.0.113.10`.

Откройте у регистратора домена раздел `DNS`, `DNS records` или `Управление
зоной` и создайте две A-записи:

| Тип | Имя | Значение | Прокси |
|---|---|---|---|
| A | `talk` | `203.0.113.10` | выключен |
| A | `turn.talk` | `203.0.113.10` | выключен |

Если используется корневой домен `example.com`, первая запись обычно имеет имя
`@`, а вторая — `turn`.

Обе записи должны работать в режиме DNS-only. В Cloudflare это серое облако,
не оранжевое. Удалите неправильные AAAA-записи для этих имён, если VPS не
настроен на IPv6.

Проверка из Windows PowerShell:

```powershell
Resolve-DnsName talk.example.com -Type A
Resolve-DnsName turn.talk.example.com -Type A
```

В обоих ответах должен быть публичный IPv4 VPS. Обновление DNS иногда занимает
от нескольких минут до нескольких часов. Не запускайте установку, пока адреса
не начали разрешаться правильно.

## 3. Открыть сетевые порты у провайдера VPS

Установщик сам настроит UFW внутри Linux, но у некоторых провайдеров есть ещё
внешний Firewall или Security Group в панели управления. В ней разрешите:

| Протокол | Порт | Назначение |
|---|---:|---|
| TCP | ваш SSH-порт, обычно `22` | управление VPS |
| TCP | `80` | выпуск и обновление HTTPS-сертификата |
| TCP | `443` | сайт, API и WebSocket |
| UDP | `443` | резервный TURN для строгих сетей |
| TCP/UDP | `3478` | STUN/TURN |
| TCP | `5349` | TURN поверх TLS |
| UDP | `49160–49260` | медиапотоки TURN |

Не закрывайте SSH-порт во время настройки.

## 4. Подготовить SMTP

Borotalk использует email для подтверждения регистрации и восстановления
пароля. Собственный почтовый сервер на VPS не нужен.

В панели выбранного SMTP-провайдера:

1. Добавьте свой домен отправителя.
2. Добавьте в DNS предложенные провайдером SPF и DKIM-записи.
3. Желательно также добавить DMARC.
4. Дождитесь статуса `Verified`.
5. Откройте раздел `SMTP credentials`.
6. Сохраните host, port, username и password/API key.

Используйте порт `587` с STARTTLS. Порт `465` в текущем установщике не
поддерживается.

Также выберите адрес отправителя на подтверждённом домене, например
`hello@example.com`.

## 5. Создать Telegram-бота

1. Откройте в Telegram официальный аккаунт `@BotFather`.
2. Нажмите `Start`.
3. Отправьте команду `/newbot`.
4. Введите отображаемое имя, например `Borotalk Requests`.
5. Введите уникальный username, обязательно заканчивающийся на `bot`, например
   `my_borotalk_bot`.
6. Скопируйте токен вида `123456789:AA...`.

Никому не отправляйте этот токен и не публикуйте его в GitHub. Webhook вручную
настраивать не нужно: установщик сделает это автоматически.

## 6. Подключиться к VPS

В панели провайдера найдите публичный IPv4 и пароль `root` либо приватный
SSH-ключ.

Откройте Windows Terminal или PowerShell:

```powershell
ssh root@203.0.113.10
```

При первом подключении SSH спросит, доверять ли fingerprint сервера. Сверьте
его с панелью VPS, затем введите `yes`. После этого введите пароль, если
используется парольная авторизация.

Если вы вошли не как `root`, команды установки запускайте через `sudo`.

## 7. Скачать и запустить установщик

В SSH-терминале VPS выполните:

```bash
curl -fL \
  https://github.com/OverFlux/borofone_chat/releases/latest/download/Borotalk-VPS-Installer.run \
  -o /tmp/Borotalk-VPS-Installer.run

sudo bash /tmp/Borotalk-VPS-Installer.run
```

Установщик:

- скачает системные зависимости;
- установит Docker, Nginx, Certbot, PostgreSQL, Redis и coturn;
- создаст случайные пароли и секреты;
- выпустит HTTPS-сертификаты;
- настроит firewall, автозапуск, health-check и backup timers;
- применит миграции базы;
- запустит API, worker и TURN;
- зарегистрирует Telegram webhook.

На вопросы установщика отвечайте так:

1. `Основной домен` — `talk.example.com`, без `https://` и без слэша.
2. `Email владельца` — ваш настоящий email. Это будет первый администратор.
3. `SMTP host` — значение из панели SMTP.
4. `SMTP port` — обычно `587`.
5. `SMTP username` — значение из SMTP credentials.
6. `SMTP password` — пароль или SMTP API key; ввод не отображается.
7. `Адрес отправителя` — например `hello@example.com`.
8. `Имя отправителя` — `Borotalk`.
9. `Telegram bot token` — токен от `@BotFather`; ввод не отображается.
10. `Username Telegram-бота` — только имя без `@`.

Секреты сохраняются только в `/opt/borotalk/.env` с ограниченными правами.

## 8. Создать первого администратора

После строки `Готово`:

1. Откройте `https://talk.example.com/register.html`.
2. Укажите тот же email владельца, который вводили в установщике.
3. Придумайте никнейм, имя и пароль.
4. Оставьте поле инвайт-кода пустым.
5. Нажмите `Продолжить по email`.
6. Откройте письмо Borotalk и нажмите `Подтвердить email`.
7. Вернитесь на страницу входа и войдите.

Только первый подтверждённый аккаунт с email из настройки
`BOOTSTRAP_ADMIN_EMAIL` автоматически становится глобальным администратором.

## 9. Привязать Telegram

1. В Borotalk откройте настройки профиля.
2. Найдите раздел `Заявки в Borotalk`.
3. Нажмите `Подключить Telegram`.
4. Разрешите открыть Telegram.
5. В диалоге с ботом нажмите `Start`.

После привязки бот будет присылать заявки на регистрацию. Кнопки `Одобрить` и
`Отклонить` требуют второго подтверждения. Если Telegram временно недоступен,
заявки всё равно остаются в веб-разделе администратора.

## 10. Как пригласить друзей

Есть два варианта.

### Регистрация без кода

Друг открывает `/register.html`, подтверждает email и ждёт одобрения. Владелец
получает заявку в Telegram и в веб-очереди.

### Одноразовый глобальный инвайт

Администратор открывает `Настройки` → `Заявки в Borotalk` → `Создать инвайт
на 72 часа` и передаёт код другу. После подтверждения email такой аккаунт
активируется без ручного одобрения.

Доступ к аккаунту не добавляет человека на конкретный сервер. Внутри Borotalk
владелец сервера может:

- создать серверный инвайт — он добавляет участника сразу;
- передать публичный ID вида `srv_...` — тогда пользователь отправит заявку
  владельцу сервера.

## 11. Проверить установку

В SSH-терминале:

```bash
sudo bash /opt/borotalk/INSTALL_VPS.sh --check
```

Также полезно проверить контейнеры:

```bash
cd /opt/borotalk
sudo docker compose \
  -p borofone-prod \
  -f deploy/docker/docker-compose.prod.yml \
  ps
```

Сервисы `postgres`, `redis`, `api`, `worker` и `coturn` должны быть запущены,
а API — иметь состояние `healthy`.

Проверьте вручную:

- регистрацию и получение письма;
- одобрение через Telegram;
- создание приватного сервера;
- текстовый чат в реальном времени;
- голос с двух разных сетей;
- демонстрацию экрана и системный звук;
- позднее подключение второго участника к уже запущенному стриму.

## 12. Обновление

Скачайте свежий установщик из нового релиза:

```bash
curl -fL \
  https://github.com/OverFlux/borofone_chat/releases/latest/download/Borotalk-VPS-Installer.run \
  -o /tmp/Borotalk-VPS-Installer.run

sudo bash /tmp/Borotalk-VPS-Installer.run --update
```

Проверка без обновления:

```bash
sudo bash /tmp/Borotalk-VPS-Installer.run --check
```

Обновление сохраняет `.env`, PostgreSQL, Redis и uploads, делает backup перед
миграциями и пересоздаёт только контейнеры приложения.

## 13. Где находятся данные

- приложение и конфигурация: `/opt/borotalk`;
- секреты: `/opt/borotalk/.env`;
- uploads: `/var/lib/borofone/production/uploads`;
- локальные backup-копии: `/var/backups/borofone/production`;
- PostgreSQL и Redis: Docker volumes.

По умолчанию backup остаётся на том же VPS. Для настоящей защиты настройте
`BACKUP_RCLONE_REMOTE` на внешнее хранилище и проверьте восстановление.

Не удаляйте `.env`, Docker volumes, `/var/lib/borofone` или
`/var/backups/borofone`, если не хотите потерять данные.

## 14. Частые проблемы

### Установщик пишет, что DNS указывает не на VPS

Проверьте обе A-записи, отключите Cloudflare proxy и дождитесь обновления DNS.

### Certbot не выпускает сертификат

Проверьте A-запись, входящий TCP `80` и отсутствие другого сервиса на порту
`80`.

### Письма не приходят

Проверьте SMTP credentials, подтверждение домена, SPF/DKIM и логи worker:

```bash
cd /opt/borotalk
sudo docker compose \
  -p borofone-prod \
  -f deploy/docker/docker-compose.prod.yml \
  logs --tail=150 worker
```

### Кнопка Telegram отключена

Проверьте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и
`TELEGRAM_WEBHOOK_SECRET` в `/opt/borotalk/.env`, затем повторите обновление.

### Сайт работает, а голос из некоторых сетей — нет

Обычно недоступен TURN. Проверьте `turn.<домен>`, UDP `443`, TCP/UDP `3478`,
TCP `5349` и UDP-диапазон `49160–49260` во внешнем firewall провайдера.

### Посмотреть состояние и ошибки

```bash
sudo bash /opt/borotalk/INSTALL_VPS.sh --check

cd /opt/borotalk
sudo docker compose \
  -p borofone-prod \
  -f deploy/docker/docker-compose.prod.yml \
  logs --tail=150 api worker coturn
```

Не публикуйте `.env` или строки логов, содержащие токены и пароли.
